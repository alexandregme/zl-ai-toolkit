# zl-ai-toolkit — Agent Configuration

Marketplace repo for the **zl** Claude Code plugin. The plugin bundles agents and skills that validate a **pnpm** project.

## Structure
- `.claude-plugin/marketplace.json` — marketplace catalog.
- `plugins/zl/.claude-plugin/plugin.json` — plugin manifest (**no `version`** → version = commit SHA).
- `plugins/zl/agents/*.md` — subagents: `test-runner`, `lint-runner`, `build-runner`, `package-check`, `installer`, the dual-review trio `codex-handoff` (Haiku), `claude-reviewer` (Opus), `review-merger` (Sonnet), and the git write agents `commit` and `pr`.
- `plugins/zl/skills/*/SKILL.md` — skills: `project-check`, `setup-permissions`, `fix-scripts`, `capture-permissions`, `dual-review`, `codex-check`.
- `plugins/zl/scripts/codex.sh` — single source of the Codex integration logic (`check` = readiness status, `review <scope> <model>` = read-only handoff). Called by the `codex-check` skill and the `codex-handoff` agent.

## Conventions
- **Names carry NO prefix** — the plugin namespace does the grouping: skills/agents show as `zl:<name>` (e.g. `zl:project-check`), so typing `zl` in the terminal surfaces the whole toolkit. Do not re-add a `zl-` prefix (it would render as the redundant `zl:zl-...`).
- **Agent colors group them in the terminal:** read-only pnpm runners are `pink`, `package-check` is `yellow`, the one writer `installer` is `cyan`, and the Codex+Claude dual-review trio (`codex-handoff`, `claude-reviewer`, `review-merger`) is `purple`, and the git write agents (`commit`, `pr`) are `green` (see the color/heart mapping in `README.md`). Write access is signalled by the agent's `tools` and description, not by color.
- **Agents are self-contained and minimal.** Each runner names the single command it may run (`pnpm test`/`lint`/`build`) so it stays disciplined even when dispatched standalone — no splitting `pnpm lint` into `pnpm eslint`, no chaining. `project-check` repeats this discipline when it orchestrates them, and `installer` carries its own (it writes and is often run alone).
- **Read-only agents never hand-edit files or run git.** Only `installer` (pnpm build-approval config), `fix-scripts` (`package.json`), `setup-permissions` (`.claude/settings.json`), and `capture-permissions` (`.claude/settings.local.json`) write via tools. Caveat: `lint-runner` runs `pnpm lint`, which **auto-fixes in place** (eslint `--fix` / prettier `--write`) — that write comes from the script, not the agent editing, so the working tree can change after a lint run. Because of that, `project-check` runs `lint-runner` **first, alone**, and only then `test-runner` + `build-runner` in parallel — a lint auto-fix landing mid-test/build would cause flaky failures.
- **Agents run on `haiku`** (`model: haiku` in frontmatter) — the runners just run one command and report, and the installer's config edits don't need more. The dual-review trio is tiered by job: `codex-handoff` is `haiku` (a thin forwarder), `claude-reviewer` is `opus` (a deep independent review), and `review-merger` is `sonnet` (reconciling two reviews against the code). Bump an individual agent's model only if it proves insufficient.
- **Code review (`dual-review` skill) is external + read-only.** It depends on the OpenAI **`codex` plugin** being installed AND logged in (`codex login`). All Codex integration logic lives in **one script, `plugins/zl/scripts/codex.sh`** (`check` and `review <scope> <model>` subcommands) — the `codex-check` skill and the `codex-handoff` agent both call it, so there is a single place to fix or extend (grow pre-review checks in the script + `codex-check` docs, not in the agent). `check` **always** emits a `STATUS=` line — `READY|<detail>`, `NOT_INSTALLED`, `CLI_UNAVAILABLE|<detail>`, or `NOT_LOGGED_IN` — guarding the JSON parse so a failed `setup --json` still yields a status, not a silent dead-end. Match the status by **prefix** (`STATUS=READY` carries a `|<detail>` suffix). **Flow:** `dual-review` runs `codex-check` **inline as the gate** (a not-ready Codex costs zero subagent tokens), then dispatches `codex-handoff` and `claude-reviewer` **in parallel** (independent by design), then `review-merger`. `codex-handoff` still re-runs `codex-check` first (declared in its `skills:` frontmatter) so it stays safe standalone. **Script resolution:** markdown blocks resolve `codex.sh` via `CLAUDE_PLUGIN_ROOT` with a newest-by-mtime fallback over `~/.claude/plugins/{cache/zl-ai-toolkit/zl/*,marketplaces/zl-ai-toolkit/plugins/zl}` (the cache keys versions by commit SHA, so a plain glob could pick a stale copy), and start with `unsetopt nomatch 2>/dev/null || true` because **zsh aborts on an unmatched glob** (bash doesn't). **Shell state does not survive between Bash tool calls**, so `codex-handoff`'s Step-2 command re-resolves the script path itself. Inside `codex.sh`, the Codex companion is found under `~/.claude/plugins/{cache,marketplaces}/openai-codex/...` — **not** via `CLAUDE_PLUGIN_ROOT` (which points at `zl`). All three agents are read-only: the script never passes `--write`; `claude-reviewer` and `review-merger` use **read-only git** (`git diff`/`git log`) — the deliberate exception to "read-only agents never run git", since a reviewer must read the diff. Default OpenAI model is `gpt-5.6` (any slug passed by the user is forwarded verbatim to `--model`); availability depends on the Codex account/plan — a rejected slug (HTTP 400 on a restricted ChatGPT-login account) should fall back to `gpt-5.5`/`gpt-5.4-mini`.
- **Assume pnpm.** (The `dual-review` skill is the exception — it reviews any repo's diff and does not touch pnpm.)
- `permissions` in `.claude/settings.json` hot-reload for the main thread, but a **subagent** keeps the permission snapshot from session start — so rules that `setup-permissions` **creates from scratch** this session reach the installer/runners only after a reload. Appending to a file that already existed needs no reload. `project-check` pauses for that reload on the first-run create.

## Releases
No `version` in the manifest → every `git push` publishes a new commit SHA. Installed users get it on demand via `/plugin update zl@zl-ai-toolkit`, or automatically at startup **only if** they set `autoUpdate: true` for the marketplace in `~/.claude/settings.json` (off by default for private marketplaces).

## Commit rules

- Commit only when the maintainer asks.
