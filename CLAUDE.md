# zl-ai-toolkit — Agent Configuration

Marketplace repo for the **zl** Claude Code plugin. The plugin bundles agents and skills that validate a **pnpm** project.

## Structure
- `.claude-plugin/marketplace.json` — marketplace catalog.
- `plugins/zl/.claude-plugin/plugin.json` — plugin manifest (**no `version`** → version = commit SHA).
- `plugins/zl/agents/*.md` — subagents: `test-runner`, `lint-runner`, `build-runner`, `package-check`, `installer`, the code-review trio `codex-handoff` (Haiku), `claude-reviewer` (Opus), `review-merger` (Sonnet), and the git write agents `commit` and `pr`.
- `plugins/zl/skills/*/SKILL.md` — skills: `project-check`, `setup-permissions`, `fix-scripts`, `capture-permissions`, `code-review`, `codex-check`.

## Conventions
- **Names carry NO prefix** — the plugin namespace does the grouping: skills/agents show as `zl:<name>` (e.g. `zl:project-check`), so typing `zl` in the terminal surfaces the whole toolkit. Do not re-add a `zl-` prefix (it would render as the redundant `zl:zl-...`).
- **Agent colors group them in the terminal:** read-only pnpm runners are `pink`, `package-check` is `yellow`, the one writer `installer` is `cyan`, and the Codex+Claude code-review trio (`codex-handoff`, `claude-reviewer`, `review-merger`) is `purple`, and the git write agents (`commit`, `pr`) are `green` (see the color/heart mapping in `README.md`). Write access is signalled by the agent's `tools` and description, not by color.
- **Agents are self-contained and minimal.** Each runner names the single command it may run (`pnpm test`/`lint`/`build`) so it stays disciplined even when dispatched standalone — no splitting `pnpm lint` into `pnpm eslint`, no chaining. `project-check` repeats this discipline when it orchestrates them, and `installer` carries its own (it writes and is often run alone).
- **Read-only agents never hand-edit files or run git.** Only `installer` (pnpm build-approval config), `fix-scripts` (`package.json`), `setup-permissions` (`.claude/settings.json`), and `capture-permissions` (`.claude/settings.local.json`) write via tools. Caveat: `lint-runner` runs `pnpm lint`, which **auto-fixes in place** (eslint `--fix` / prettier `--write`) — that write comes from the script, not the agent editing, so the working tree can change after a lint run.
- **Agents run on `haiku`** (`model: haiku` in frontmatter) — the runners just run one command and report, and the installer's config edits don't need more. The code-review trio is tiered by job: `codex-handoff` is `haiku` (a thin forwarder), `claude-reviewer` is `opus` (a deep independent review), and `review-merger` is `sonnet` (reconciling two reviews against the code). Bump an individual agent's model only if it proves insufficient.
- **Code review (`code-review` skill) is external + read-only.** It depends on the OpenAI **`codex` plugin** being installed AND logged in (`codex login`). The readiness gate lives in its **own skill, `codex-check`** (a separate, extensible step: it resolves the companion, runs `codex-companion.mjs setup --json`, and **always** emits a `STATUS=` line — `READY|<detail>`, `NOT_INSTALLED`, `CLI_UNAVAILABLE|<detail>`, or `NOT_LOGGED_IN` — guarding the JSON parse so a failed `setup` still yields a status, not a silent dead-end). `codex-handoff` runs `codex-check` first (declared in its `skills:` frontmatter) and stops unless the status line **starts with** `STATUS=READY` (match by prefix — the ready line has a `|<detail>` suffix). Grow pre-review checks by adding to `codex-check`, not by editing the agent. **Shell state does not survive between Bash tool calls**, so `codex-handoff` re-resolves the companion path inside its Step-2 command rather than reusing a variable from the check. It resolves the path (`~/.claude/plugins/{cache,marketplaces}/openai-codex/.../codex-companion.mjs`), **not** via `CLAUDE_PLUGIN_ROOT` (which points at `zl`). All three agents are read-only: `codex-handoff` never passes `--write`; `claude-reviewer` and `review-merger` use **read-only git** (`git diff`/`git log`) — the deliberate exception to "read-only agents never run git", since a reviewer must read the diff. Default OpenAI model is `gpt-5.6` (any slug passed by the user is forwarded verbatim to `--model`); availability depends on the Codex account/plan — a rejected slug (HTTP 400 on a restricted ChatGPT-login account) should fall back to `gpt-5.5`/`gpt-5.4-mini`.
- **Assume pnpm.** (The `code-review` skill is the exception — it reviews any repo's diff and does not touch pnpm.)
- `permissions` in `.claude/settings.json` hot-reload for the main thread, but a **subagent** keeps the permission snapshot from session start — so rules that `setup-permissions` **creates from scratch** this session reach the installer/runners only after a reload. Appending to a file that already existed needs no reload. `project-check` pauses for that reload on the first-run create.

## Releases
No `version` in the manifest → every `git push` publishes a new commit SHA. Installed users get it on demand via `/plugin update zl@zl-ai-toolkit`, or automatically at startup **only if** they set `autoUpdate: true` for the marketplace in `~/.claude/settings.json` (off by default for private marketplaces).

## Commit rules
- Conventional commits. NO co-author / "Generated with" lines. Clean messages.
- Commit only when the maintainer asks.
